## Продуктовый контекст

NOW — это real-time social operating system для города.

Это не dating app, не обычная social network и не messenger.

Пользователь должен за первые секунды понять:

- что происходит рядом;
- что доступно прямо сейчас;
- где это происходит;
- сколько людей уже присоединилось;
- сколько мест осталось;
- какое действие нужно сделать дальше.

Главная идентичность продукта — CITY LIGHTS. Город должен ощущаться живым, но интерфейс должен оставаться простым, безопасным и production-ready.

Не добавляй новые функции, которых нет в текущем MVP. Сохрани существующую функциональность.

Не используй emojis в UI.

## Обязательные требования к визуальной системе

Следуй исходному дизайн-промту и используй semantic tokens, а не разбросанные hardcoded значения.

Основные значения:

- background: #050608
- surface/card: #0E1014
- elevated surface: #151922
- border: #232836
- primary text: white
- secondary text: #B7BFCA
- muted text: #7B8593
- accent: electric blue

Создай или доведи до полноценного состояния semantic tokens для:

- primary;
- secondary;
- danger;
- success;
- warning;
- disabled;
- overlay;
- glow;
- shadow;
- focus/ring;
- activity-specific glow.

Activity glow:

- Walk — soft blue;
- Coffee — warm amber;
- Sport — green;
- Games — purple;
- Music — pink.

Не добавляй Music как новую функциональность, если её нет в текущем MVP. Можно подготовить токен для будущего использования.

Для каждой activity glow предусмотрены состояния:

- idle;
- breathing;
- join pulse;
- celebration burst.

Breathing animation должна быть мягкой, около 2400ms, без агрессивного мигания.

Используй строгую spacing system на основе 8pt grid:

- 4;
- 8;
- 12;
- 16;
- 24;
- 32;
- 40;
- 48;
- 64.

Не создавай второй независимый token source. В этом проекте `tokens.json` является источником токенов, а CSS и generated token files должны обновляться через существующий генератор.

Не редактируй вручную:

- artifacts/now-design-system/src/index.css;
- artifacts/now-design-system/src/generated/tokens.tsx.

После изменения tokens.json запускай существующий token generation script.

Typography:

- используй системный стек с SF Pro Display / SF Pro Text fallback;
- создай понятную иерархию Hero, H1, H2, H3, Body Large, Body, Caption, Label;
- не делай основной интерфейс мелким;
- сохраняй читаемость и dynamic type-friendly scale.

Motion:

- 120ms — press, focus, micro feedback;
- 180ms и 250ms — state changes, filters, chips;
- 350ms — cards, bottom sheets, major transitions;
- 500ms — hero moments, countdown, success;
- обязательно поддержи prefers-reduced-motion;
- не используй случайные timing values без причины;
- документируй motion rules.

Touch/accessibility:

- минимум 44pt для интерактивных целей;
- keyboard focus;
- screen-reader labels;
- high contrast;
- reduced motion;
- one-thumb usability;
- не прячь важную информацию только в hover.

## API и функциональность

Не подменяй API реальным UI mock data там, где уже есть hooks.

Текущие hooks находятся в:

lib/api-client-react/src/generated/api.ts

Перед кодированием проверь точные сигнатуры grep-командой:

grep "^export " lib/api-client-react/src/generated/*.ts | grep -E "function use|const use|QueryKey"

Основные hooks, которые уже используются:

- useHealthCheck
- useListMeetups
- useCreateMeetup
- useGetMeetup
- useJoinMeetup
- useLeaveMeetup
- useCheckInMeetup
- useCompleteMeetup
- useListMessages
- useCreateMessage
- useGetShareCard
- useGetProfile
- useUpdateProfile
- useGetAuthMe
- useLogout
- useListInterests

Импортируй hooks только из:

@workspace/api-client-react

Не импортируй их из относительных путей.

Следи за React Query invariants:

- после mutation обновляй или invalidates нужные queries;
- mutation result должен быть виден без ручного refresh;
- loading/error/empty branches должны быть безопасными;
- не используй данные до проверки существования;
- после navigation и reload состояние должно оставаться корректным;
- не ломай существующие enum values, routes и API contracts.

API сейчас demo/in-memory. Не выдавай его за production persistence или настоящую OTP-auth. Если backend не требуется для визуального redesign, не расширяй backend без необходимости. Если API всё же меняется, используй OpenAPI-first workflow, regenerate client и проверь frontend contracts.

4. Проверь mobile и desktop.
5. Используй canvas для визуального сравнения и не iframe main app напрямую.
6. Если создаёшь несколько вариантов, прочитай design-exploration skill и делай варианты разными design hypotheses, а не простыми reskins.
7. Если выбранный mockup будет переноситься в production через approved design, используй mockup-graduate.
8. Не удаляй mockup reference автоматически.

Не выдавай mockup за готовое production-приложение. Production version должна использовать реальные API hooks, routing, loading/error states и accessibility.
