# PWA Roadmap: NOW / IRL (Spontaneous Offline Activities)

## 1. Executive Summary
Данный документ описывает архитектурный план и требования для внедрения Progressive Web App (PWA) возможностей в сервис спонтанных встреч **NOW / IRL** в будущих фазах.
В текущей фазе *Real MVP Foundation* PWA намеренно не активирован для минимизации сложности и фокусировки на надежной PostgreSQL-персистентности, Zero-PII аутентификации и возрастном гейте 18+.

---

## 2. Ключевые цели PWA в следующих фазах

1. **Мобильный опыт первого класса (Mobile First / App-like UX):**
   - Запуск без интерфейса браузера (`display: standalone`).
   - Изоляция безопасной области (safe-area insets для iOS и Android).
   - Быстрый отклик на жестовое управление и свайпы без перезагрузки страниц.

2. **Работа в условиях нестабильной мобильной сети (Offline Resiliency):**
   - Кэширование статических ассетов (SVG-силуэты, пиктограммы активностей, шрифты).
   - Офлайн-экран с инструкциями безопасности и контактами экстренных служб (SOS 112).
   - Индикация потери связи во время активной координации встречи.

3. **Своевременные уведомления (Push Notifications) без спама:**
   - Web Push API через VAPID-ключи.
   - Строго ограниченные триггеры:
     - Огонёк собрал минимальный кворум участников.
     - Напоминание за 10 минут до старта.
     - Сообщение координации в чате активной встречи.
   - Полный запрет на маркетинговый и рекламный push-спам.

## 3. Архитектура внедрения

  "start_url": "/",

  "theme_color": "#F97316",

    }

### 3.2. Стратегия кэширования Service Worker (Workbox / Serwist)
- **Static Assets (CSS, JS, Fonts, Icons):** `CacheFirst` с версионированием по хешу сборки.
- **Discovery Cards (`/api/meetups`):** `NetworkFirst` с таймаутом 2.5 секунды (актуальность активных Огоньков превыше всего).
- **Active Meetup Live State (`/api/meetups/[id]`):** `NetworkOnly` (координация в реальном времени не должна показывать устаревший кэш).
- **Offline Fallback:** `/offline` страница с локальными подсказками безопасности и номером 112.

### 3.3. Приватность и батарея
- Service Worker **не должен** постоянно опрашивать GPS пользователя в фоновом режиме (Zero Background Geolocation Tracking).
- Геолокация запрашивается разово только по явному действию пользователя на карте.

## 4. Этапы реализации (Milestones)

| Этап | Задачи | Критерии приёмки |
| :--- | :--- | :--- |
| **PWA Phase 1** | Манифест, мета-теги, фавиконки, базовый Service Worker | Успешный аудит Lighthouse PWA, появление кнопки «Установить на экран» |
| **PWA Phase 2** | Offline fallback, кэширование статики, обнаружение отсутствия сети | При отключении Wi-Fi/LTE приложение показывает понятный офлайн-экран с SOS 112 |
| **PWA Phase 3** | Web Push подписки, отправка push о кворуме через backend | Пользователь получает пуш при сборе компании, даже если приложение свернуто |
