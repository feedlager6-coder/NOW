# NOW / IRL — Rebuild Plan & Technical Evaluation

**Рабочее название продукта:** NOW / IRL  
**Финальное название:** Конфигурируемое через `app.config.ts` (`NEXT_PUBLIC_APP_NAME="NOW"`)  
**Миссия:** «Собери компанию рядом за несколько минут. Никаких свайпов. Только реальные встречи сейчас.»  
*English:* «Open the app. Press one button. Meet real people nearby in minutes.»  
**Версия:** 2.0.0 (Phase 0: Architecture Selection & Pivot Specification)  
**Статус:** Draft for Review / Pre-Implementation  

---

## 1. Контекст перехода и ликвидация старой модели

Старая концепция сервиса MoodCall (платные компаньоны, почасовая оплата, заказ конкретного человека, «альтушки по вызову», клиент-исполнитель) полностью признана несоответствующей долгосрочным целям, несущей критические репутационные, этические и юридические риски (ст. 241 УК РФ, ассоциации с эскортом и проституцией).

### 1.1. Что полностью ликвидируется из продукта:
- Сущности `performer`, `client`, `booking`, `payout`, `hourly_rate`, `escrow`;
- Любые элементы маркетплейса «покупки человека» или почасовой аренды времени;
- Сексуализированный или псевдо-романтический контекст;
- Оплата за встречу между пользователями (продукт — бесплатная координация совместных групповых активностей);
- Все старые UI-тексты, seed-профили и эндпоинты бронирования.

### 1.2. Что безопасно переиспользуется:
- **Инфраструктурный фундамент Среза 1:** Настройка TypeScript, Tailwind CSS, линтер, Vitest, Playwright, конфигурация окружения (`src/lib/env.ts`);
- **Zero-PII Logger (`src/lib/logger.ts`):** Строгий denylist с доказанной защитой от утечек PII в логи;
- **Архитектура PostgreSQL + Drizzle ORM:** Пул соединений, транзакционные блокировки `SELECT ... FOR UPDATE`, проверка схем в тестах;
- **Server-Side Whitelist публичных зон:** Принцип жесткого ограничения локаций только проверенными публичными точками (`DEMO_PUBLIC_ZONE_1..3`).

## 2. Сравнение архитектурных вариантов: Вариант A vs Вариант B

По требованию проанализированы два технических пути реализации MVP:
- **Вариант A:** Next.js 14+ PWA + PostgreSQL 15+ + Drizzle ORM (Текущий стек)
- **Вариант B:** React Native Expo + Supabase (PostgreSQL + Realtime + Storage + Auth)

| Критерий оценки | Вариант A: Next.js PWA + PostgreSQL + Drizzle | Вариант B: React Native Expo + Supabase |
| :--- | :--- | :--- |
| **Скорость разработки MVP в Antigravity / Replit** | **Высокая (1-2 дня).** Кодовая база уже развернута, зависимости установлены, Drizzle и Vitest работают прямо в текущем окружении. | **Низкая (1-2 недели).** Требует с нуля инициализировать Expo-проект, настраивать Metro bundler, полифилы Node.js, мобильные эмуляторы. |
| **Стоимость инфраструктуры** | **Минимальная ($0 на старте).** Единый контейнер Node.js на Replit/Vercel + любой бесплатный PostgreSQL (Neon/Supabase PG/Replit). | **Средняя / Растущая.** Платные квоты Supabase на Realtime-соединения (MAU) и EAS Build подписки. |
| **Push-уведомления** | Web Push API (Service Worker) + In-App баннеры и звуковые сигналы. Достаточно для веб-MVP. | Нативные APNs / FCM через Expo Notifications. Преимущество на iOS при закрытом приложении, но требует аккаунтов Apple Developer ($99/год) и Google Play ($25). |
| **Карты и геометрия** | Карта на базе Leaflet / MapLibre / SVG-псевдокарты с огоньками без привязки к проприетарным SDK. | `react-native-maps`, требующий ключей Google Maps / Apple Maps API, настройки pod-зависимостей и нативных разрешений. |
| **Realtime-механика** | Server-Sent Events (SSE) или адаптивный Smart Polling (каждые 3 сек для активного митапа). Не требует отдельных платных серверов. | Встроенный Supabase Realtime (WebSockets). Удобно, но накладывает лимиты одновременных каналов на бесплатном тарифе. |
| **Безопасность секретов** | Все секреты (HMAC phone salt, sessions, DB credentials) живут строго на сервере в Node.js / Route Handlers. Клиентский бандл изолирован. | Требует тщательной настройки RLS в Supabase. Риск утечки service_role ключа в бандл мобильного приложения. |
| **Тестирование** | Мгновенный прогон в headless-режиме через Vitest и Playwright с эмуляцией мобильного вьюпорта 390x844 прямо в CI. | Тестирование React Native компонентов через Jest/RNTL и Detox требует эмуляторов iOS/Android, недоступных в легких средах. |
| **Доступность в России и Дагестане** | **100% доступность.** Открывается по прямой ссылке в любом браузере (Chrome, Safari, Яндекс.Браузер), устанавливается на экран «Домой» (PWA). Нет риска блокировки в App Store / Google Play. | **Высокий риск.** Проблемы с публикацией в App Store для РФ, задержки модерации Apple (до 7 дней), возможные сетевые сбои Supabase без VPN. |
| **Риск переписывания текущего проекта** | **Минимальный.** 80% конфигурации, тестовые пайплайны и утилиты безопасности остаются нетронутыми. | **Критический.** Полный сброс текущего прогресса, необходимость заново решать проблемы сборки мобильного приложения. |

### 2.1. Итоговый выбор для MVP: ВАРИАНТ A (Next.js PWA + PostgreSQL + Drizzle)

> [!IMPORTANT]
> **Рекомендация CTO:** Для MVP выбирается **Вариант A (Next.js PWA + PostgreSQL + Drizzle)**.
> **Обоснование:**
> 1. Сверхбыстрый Time-to-Market: сохраняется уже проверенная и работающая инфраструктура Среза 1 (PostgreSQL, Drizzle, Vitest, Playwright, Zero-PII Logger).
> 2. Отсутствие барьеров дистрибуции: PWA не требует многодневной модерации в Apple App Store и Google Play, работает на смартфонах сразу по короткой ссылке.
> 3. Независимость от внешних SaaS-провайдеров: полный контроль над базой данных без риска внезапных блокировок или санкционных ограничений.
> 4. Чистый путь к Expo: Приложение строится на чистом Service Layer. Если после пилота в Махачкале потребуется нативный мобильный клиент, REST API останется неизменным, а Expo-приложение будет создано как отдельный UI-клиент к готовому бэкенду.

## 3. Этапы реализации (Roadmap)

- **Фаза 0 (Текущая):** Анализ, выпуск полного комплекта документации (Product Bible, Rebuild Plan, Migration Plan, Architecture, Threat Model, Data Protection, API Spec, DB Schema, Test Plan, Deployment, Risk Register), фиксация выбора стека. Остановка и ожидание утверждения.
- **Фаза 1:** Чистый ребилд фундамента (Clean Rebuild): удаление старых сущностей, архивация старой миграции, создание новой схемы базы данных (19 таблиц), сид DEMO-активностей и зон, базовый UI Home с неоновыми «Огоньками» и таймером.
- **Фаза 2:** Механика создания активности и Join: форма «Собрать компанию» (<15 сек), транзакционный `joinMeetup()` с защитой от гонок на capacity, обратный отсчет (Countdown).
- **Фаза 3:** Анонимная выдача (Anonymous Discovery), правила приватности до старта, изолированный одноразовый групповой чат активности с 12-часовым retention.
- **Фаза 4:** Репутация (взаимные оценки участников `criteria: showed up, on time, respectful`), подача жалоб (Reports), блокировка пар пользователей (Blocks), контур Safety Help (`tel:112` + дисклеймер).
- **Фаза 5:** Виральный движок: автоматическая генерация Share-Card (картинка без PII со временем, категорией и числом участников), интеграция аналитических событий (внутренний адаптер).
- **Фаза 6:** Закрытый пилотный запуск в DEMO-среде; подготовка юридической оферты и регламентов до публичного открытия.
